# Mommantum — Security, Code, SEO and Lighthouse Review (2026-11-09)

**How this was done:**
- Three independent reviews ran in parallel: a security engineer, a CTO code review, and an SEO/AEO/GEO specialist. Each read the source code.
- Lighthouse 12 ran on a local production build, on 6 pages, for mobile and desktop.
- I re-checked the important findings myself in the code (marked ✔ verified).
- Everything ran **without the live database**. Pages used their built-in fallback content, and production may differ for blog posts and case studies.

## 3. Security findings

| # | Sev | Finding | Fix |
|---|---|---|---|
| S1 | **Check now** | `profiles` RLS policies are not defined in the repo. If a "users can update their own profile" policy exists, a pending user could set themselves to admin or switch off their own 2FA flag through the public API. | Run `select * from pg_policies where tablename='profiles'`. Allow SELECT of your own row only, and add a trigger that blocks role/status/mfa changes unless the caller is the service role. |
| S2 | Medium ✔ | **Open redirect:** `/api/preview/exit?to=/\evil.com` sends visitors to evil.com. | Compare the URL origin instead of checking for a leading slash. |
| S3 | Medium | 2FA can fail open for the owner if the profile lookup errors (the flag is cached for 60 s); `setMfaFlag` ignores errors. | Fail closed. Read verified factors from Supabase Auth instead of the mirrored flag. |
| S4 | Medium ✔ | **Formula injection** into the leads Google Sheet (`USER_ENTERED`): a name like `=IMPORTXML(...)` runs as a formula in the team sheet. | Use `RAW`, or prefix with `'`. |
| S5 | Medium | `leads_sheet_url` sits in `site_setting`, which is readable with the public anon key. | Move it to env or a table only the server can read; keep the Sheet private. |
| S6 | Medium | The contact auto-reply echoes the visitor's name and subject to any address, which can be abused for spam/phishing when Turnstile is off. | Require Turnstile in production; make the auto-reply generic; add a daily cap. |
| S7 | Medium | No Content-Security-Policy. | Add a CSP (start with Report-Only) allowing GTM, Turnstile and Supabase. |
| S8 | Low–Med | One preview link enables draft mode for **all** drafts in that browser. | Bind preview to the slug with a signed cookie. |
| S9 | Low–Med | Drafts may be readable through the anon key if `post` RLS is `using (true)`. | Restrict anon SELECT to published, non-deleted posts. |
| S10 | Low | Sanitiser allows `style` and `id` on all tags; the external-link check treats `mommantum.com.evil.com` as internal. | Drop `style` and `id`, and anchor the domain check. |
| S11 | Low | The admin blog preview renders raw HTML. | Sanitise the preview too. |
| S12 | Low | Marketers can read every lead's personal data, and 2FA is never required for marketers. | Mask PII for marketers, or restrict access. |
| S13 | Low | Login shows "not approved" for a correct password but "invalid" for a wrong one, so it reveals valid passwords; login has no origin check. | Same message for both; add the origin check. |
| S14 | Low ✔ | `increment_redirect_hits` is callable by anyone; SECURITY DEFINER functions have no fixed `search_path`. | Revoke execute; set `search_path`. |
| S15 | Low | IP-hash salt and preview secret fall back to other secrets or a constant. | Require dedicated secrets. |
| S16 | Low | In-memory rate limits apply per server instance; attackers can call Supabase Auth directly. | Tighten Supabase Auth rate limits in the dashboard. |

**Done well:**
- Logins are cryptographically verified and fail closed, with no algorithm confusion.
- Roles come only from the database. Every admin API checks origin, role, path and 2FA.
- Owner protection works in both the app and the database.
- Upload magic-byte checks, constant-time key checks, HMAC-signed previews.
- Append-only audit log; PII is hashed or kept out of logs.
- Strong security headers.

## 4. Code review (CTO)

| # | Sev | Finding | Fix |
|---|---|---|---|
| C1 | High ✔ | The in-memory SEO cache sits **inside** `unstable_cache`, so another server instance can write stale data back into the shared cache for up to an hour after an admin saves. | Remove the memory layer from `getSeoSetting`/`getSiteSetting`, or move it outside with a TTL no longer than the tag's. |
| C2 | High | In-memory caches (roles, rate limits, page registry) are cleared only on the instance that handled the change, so a demoted user can keep access for up to 60 s elsewhere. | Document the window, or move that state to Supabase. |
| C3 | High ✔ | The standard API response helper (`ok`/`fail`) exists but none of the 41 routes use it, so response shapes vary. | Adopt it everywhere, with pagination `meta`. |
| C4 | High | Admin write routes (blog, services, case studies, products) use field allowlists but **no Zod**, so bad FAQ or array data can break the JSON-LD. | Add Zod schemas to every write. |
| C5 | Med ✔ | Lead retry re-sends the team email when only the auto-reply failed, and exhausted leads can block newer ones. | Track the two emails separately; filter on attempts. |
| C6 | Med ✔ | `publishDuePosts` doesn't confirm the row actually changed, so it can announce a post that wasn't published. | Add `.select()` and check the row count. |
| C7 | Med | Background jobs (`after()`, crons) have no try/catch around delivery. | Wrap them and notify on failure. |
| C8 | Med | Slug checks race with inserts and return 500 instead of 409. | Map unique-violation errors (23505) to 409. |
| C9 | Med | Hardcoded contact details, social links and FAQs in components. | Move to `site.ts` or the database. |
| C10 | Med | No central env validation; missing env values fall back to placeholders silently. | Add a Zod env module that fails closed in production. |
| C11 | Med ✔ | 11 Editz files import `framer-motion`, which isn't in `package.json` (it resolves through `motion`). | Switch them to `motion/react`. |
| C12 | Med | The footer (884 lines) is a client component on every page. | Make it a server component with a small client accordion. |
| C13 | Low | Unused dependencies: `@headlessui/react`, `@radix-ui/react-accordion`, `webpack`, babel, and `@medusajs/*` pinned to `latest`. `googleapis` is heavy. | Prune them; pin versions. |
| C14 | Low | 13 files exceed 400 lines (SharedEntityEditor 956, footer 884, BlogEditor 780, users page 768…). | Split them gradually. |
| C15 | Low | About 43 `any` types; leftover headers for routes that don't exist; 24 overlapping docs files. | Clean up. |
| C16 | Low | No tests for: rate-limit, ttl-cache, leads retry, sanitize, middleware, route handlers. | Add tests. |

**Done well:** clean auth model; middleware doesn't touch the database for public pages; the contact pipeline (save first, deliver later); a bounded TTL cache; CI gates (typecheck, lint, test, build, Lighthouse); a lint rule banning raw colours; strong schema and AI tests.

## 5. SEO / AEO / GEO

| # | Pri | Finding | Fix |
|---|---|---|---|
| E1 | High ✔ | **Homepage H1 is the typewriter slogan** ("We make it faster, and scalable"), with no keyword. | Use a fixed H1 such as "Performance Marketing & D2C Growth Agency in Jaipur"; move the typewriter text to a `<p>`. |
| E2 | High | Hub H1s are slogans, and some are garbled by a missing space before a line break: "Built to growyour brand.", "We help D2C brandsgrow". | Use keyword H1s and add `{" "}` before each `<br>`. |
| E3 | High ✔ | **Editz FAQ answers only render after a click**, so the FAQ markup doesn't match the visible HTML. | Always render the answers and hide them with CSS. |
| E4 | High | 46+ elements start at `opacity:0` until JavaScript runs, including the Editz H1, which hurts LCP and AI crawlers. | Start above-the-fold content visible (`initial={false}`). |
| E5 | High ✔ | Render-blocking Google Fonts (5 families). | Self-host with `next/font` and cut to 2–3 families. |
| E6 | Med | Inconsistent business details (NAP): a second phone number on /contact isn't in the schema, the email is on the `.in` domain, the founder title differs, and `sameAs` lacks LinkedIn and Google Business Profile. | Make them consistent; extend `sameAs`. |
| E7 | Med | No founder Person entity and no author pages (weak E-E-A-T). | Add a Person `@id` and author pages; link BlogPosting authors to them. |
| E8 | Med | Local SEO: Organization only, `geo` missing, the map link points to Cochin. | Add `ProfessionalService` typing, opening hours, `geo`, and the correct Google Business Profile map link. |
| E9 | Med | Full Organization data appears only on the homepage. | Emit a small Organization/WebSite node on every page. |
| E10 | Med | Duplicate FAQ markup on /faq and on the legal pages. | Mark up each Q&A on one canonical page. |
| E11 | Med | Internal links always use the exact-match keyword as anchor text; "case studies" is linked globally. | Rotate anchor text; link the first match only. |
| E12 | Med | Sitemaps and /blog depend on the database (a services sitemap with no DB is empty; empty /blog has no H1). | Fall back to built-in services; render the H1 when there are no posts. |
| E13 | Med | Per-page share images in `/og/pages/` are unused. | Wire them into each page's metadata. |
| E14 | Med | Case studies have no Article schema. | Add Article/CreativeWork with `about`/`mentions`. |
| E15 | Low | Nested `<main>`; `lang="en"` instead of `en-IN`; no `/llms.txt`; `areaServed: "Worldwide (…)"` isn't a valid place. | Small fixes. |

**Done well:**
- Metadata and schema come from one source.
- Canonicals, OG/Twitter and `en_IN` locale are correct; preview deployments are noindex.
- One connected schema graph per page; breadcrumbs match the visible ones.
- FAQ markup matches visible content (except Editz).
- robots.txt is open to AI answer engines.
- Real `lastmod` dates in sitemaps; correct 404s and 301s.
- Careful internal linker; unique titles.
